Uebit

Making web development teachable: a visual site builder that exposes real HTML, CSS and JavaScript instead of hiding them.

React 19 Vite 8 JavaScript Blockly Tailwind CSS 4 HTML/CSS
Leonardo Moreira Published October 2026

Abstract

Uebit is a personal open-source teaching project designed to help children, teenagers and beginners discover how websites work. Learners assemble a page visually, experiment with logic blocks, inspect editable source code, and export a site that runs without the editor.

Project status: Active early-stage development. The live demo and source are available; features may evolve.

1. The teaching problem

After teaching programming to children, teenagers, and adults, I kept running into the same gap: many beginners can arrange visual elements or follow Blockly exercises, but struggle to connect those ideas to the HTML, CSS, and JavaScript used on real websites. Uebit grew out of that practical teaching problem, not a commercial product brief.

A visual editor should be the beginning of learning the web—not a wall hiding how the web works.

— Uebit's guiding idea

The learning path begins with a tangible result: drag a heading onto a page, change its style, then examine the source code behind that change. Gradually, students can add interactivity using blocks and transition to written JavaScript.

2. Building pages as a learning experience

Visual composition

Uebit provides drag-and-drop page building with common elements such as headings, paragraphs, buttons, images and containers. Rather than hiding layout entirely, the inspector exposes practical properties including spacing, colors, the box model and Flexbox behavior.

Programming with blocks

The Blockly-based editor connects events, conditions, loops and actions to the page the learner is building. Students can experiment with a button that responds to a click, a small counter or a change of style without first memorizing every piece of JavaScript syntax.

Code is part of the lesson

One of the project's core decisions is to let learners inspect and edit the resulting HTML, CSS and JavaScript. The purpose is not to replace code with blocks indefinitely; it is to make the connection between the two visible.

3. Architecture and technologies

The interactive editor is developed with React 19, Vite 8, Tailwind CSS 4 and Google Blockly. These libraries support the authoring environment. They are not required for someone to run the resulting website after export.

Editor versus published result

The editor manages a document model, styles and interactions. Export translates the project into a standalone package with index.html, style.css and script.js. This separation keeps the learner's work independent from the React authoring interface.

Why explicit Flexbox controls?

It would be easy to hide layout behind presets. Instead, keeping familiar CSS concepts visible allows teachers to explain why a container aligns, wraps or distributes its children in a particular way.

4. Preview, experimentation and export

The editor includes desktop and mobile preview modes so that students can see how their pages respond to different viewport sizes. A play/stage mode focuses on the website itself, temporarily removing the authoring interface.

Export is designed for a straightforward next step: a downloadable ZIP that contains the three core web files. The output can be opened locally and hosted on static services such as GitHub Pages without running a React application or provisioning an application server.

5. Trade-offs and open challenges

Visual freedom versus understandable code

A visual canvas encourages experimentation, but it can also create unnecessarily complicated layout structures.

Approach: Teach layout concepts explicitly and keep generated web code available for inspection rather than concealing everything behind templates.

Blocks versus editable JavaScript

Generating behavior from blocks is useful only if learners can trace what their interactions do.

Approach: Connect block logic to the actual page and offer a code-editing pathway. Preserving meaningful round-trip synchronization remains a complex educational and technical problem.

Teaching beginners without removing agency

The project targets young learners and first-time web developers. A highly polished interface is less useful if it prevents curiosity or experimentation.

Approach: Keep the interface playful, expose tangible results and make the project openly available to educators and contributors.

6. What comes next

Uebit is an evolving personal and educational project. Its roadmap is driven by classroom feedback: refining blocks, improving the editor's ergonomics, and making transitions between visual composition and written code easier to understand.

I am sharing its source code early because examples, classroom use and contributions are more useful to this project than presenting it as a finished commercial product.
